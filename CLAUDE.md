## Stack
- Worker Node 24 + TypeScript (tsx) em worker/, agendado no GitHub Actions (.github/workflows/sync.yml, a cada 3 h, UFS=BR) e disparado também pelo pg_cron (sync-pncp).
- Supabase (Postgres), projeto edital-map em sa-east-1, plano grátis (teto 500 MB). Schema em supabase/migrations/; mudança só com nova migration.
- Supabase: ref omtwaflypzlebjoeubvp, região sa-east-1.
- Site: Next.js 16 (App Router) + React 19 + Tailwind 4 + maplibre-gl 6 com fundo OpenFreeMap positron (reserva sem fundo se ele não responder), na Vercel (região gru1).
- Pagamento: Cakto (não Stripe). Resend para alertas e login por e-mail.

## Regras
- O worker grava pelo supabase-js com SUPABASE_SERVICE_ROLE_KEY. Essa chave nunca vai para o navegador nem para o git. O mesmo vale para SUPABASE_DB_URL (só no .env local).
- "Aberta" = encerramento_em > now() e situação diferente de Revogada (2) e Anulada (3); nas consultas do site isso fica só em `public.em_aberto` (0011); suspensa (4) continua aberta, com etiqueta. Não confiar no endpoint /proposta para isso; ele só serve para encontrar contratações na carga.
- Datas do PNCP vêm sem fuso: converter com deBrasilia() (America/Sao_Paulo) antes de gravar.
- Link do edital: link_origem; se vazio, https://pncp.gov.br/app/editais/{cnpj}/{ano}/{sequencial}.
- valor_estimado nulo ou 0 = "Valor não informado".
- Em contratos (Fase 4), guardar só fornecedor PJ (LGPD).
- PNCP: tamanhoPagina máx. 50 (51 → 400); modalidade obrigatória; vazio = 204; itens paginam (pedir 50, teto 200 páginas); **consulta limitada a 20 chamadas/min por IP (ritmo em `criarRitmo`, rajada 10); 429 espera 30/60/120 s; 5xx/timeout 2/4/8 s; a base de itens não tem esse limite**; janela do sync = última data boa (com releitura de ontem até 03h); timestamp da compra só avança depois dos itens.
- Modalidades da v1: 6, 8, 4, 7, 12.
- UFS vazio ou BR = país inteiro numa consulta só (sem uf no PNCP); chaves de estado atualizacao:BR:<modalidade>.
- Itens não ficam no banco: cada contratação guarda itens_palavras (tsvector sem posições, mesma configuração de texto) e itens_resumo (jsonb); a lista de itens do edital vem do PNCP na hora (lib/servidor/itensPncp.ts), com "Itens indisponíveis agora" se falhar.
- Retenção: contratação encerrada há mais de 7 dias ou sem encerramento_em é apagada todo dia (pg_cron retencao-contratacoes, 04:45 UTC) e o worker não a grava.
- Medir o banco com npm run db:medir; VACUUM FULL só com npm run db:medir -- --vacuum, fora das rodadas do sync.
- Interface em português do Brasil, com o vocabulário "edital" e "Alertas". Visual: design system Edital Map (não as cores do canvas).
- TDD: teste primeiro (vitest). npm test e npm run typecheck passam antes de cada commit.
- Vercel: projeto edital-map no time JPM Company, região gru1, publicado pela CLI (`vercel deploy --prod`), sem Git ligado; `.vercelignore` impede o envio do `.env`.
- maplibre-gl 6 (só ESM): o worker vem do pacote via `setWorkerUrl` em components/Mapa.tsx (o Turbopack zera o import.meta.url).
- Site: dados só pelo servidor (lib/servidor/*, `server-only`); cache de 5 min; eventos e pedidos de alerta só pelas rotas /api.
- SEO: site aberto ao Google (robots libera tudo menos /api/; `/` com parâmetro de busca e edital fora de `em_aberto` em `noindex, follow`; canônico sempre em https://www.editalmap.com.br, `SITE_URL` em lib/seo/site.ts). Páginas fixas `/licitacoes`, `/licitacoes/[assunto|uf]` e `/licitacoes/[assunto]/[uf]` (14 assuntos de lib/seo/assuntos.ts, um por grupo de termos.ts; com assunto a lista vem por relevância; não contam uso; zero editais = `noindex`). Robô (lib/robos.ts) não recebe cookie no proxy, então nada conta nem grava uso_diario. Sitemap em rotas próprias: /sitemap.xml (índice) e /sitemaps/paginas.xml e /sitemaps/editais-N.xml (40.000 por arquivo; 0012/0013: `abertos_por_uf`, `total_editais_abertos`, `editais_abertos_sitemap`). `GOOGLE_SITE_VERIFICATION` liga a meta tag do Search Console.
- Busca: termos relacionados em lib/relevancia/termos.ts (código versionado, grupos por assunto, até 20 relacionados intercalados), `-palavra` exclui pelo objeto; relevância 0–100 determinística: o banco ordena (`pontuacao_busca`, pesos iguais a `PESOS` de lib/relevancia/pontuacao.ts, guardados em teste) e o site mostra nota e explicação só com termos que bateram. Vista (lista|mapa, padrão mapa; `vista=lista` no endereço), ordem e página vão no endereço e nunca contam busca.
- Conta: login por código de 6 dígitos (Supabase Auth, SMTP pelo Resend, modelo em supabase/templates/codigo.html); sessão em cookies httpOnly via @supabase/ssr só em lib/servidor/sessao.ts e lib/sessaoProxy.ts (chave publicável SUPABASE_ANON_KEY, só no servidor); o proxy renova a sessão só em /entrar, /radar*, /api/conta*, /api/radar*; user_id só de usuarioAtual() (getUser); toda rota POST da conta/radar chama recusaForaDoSite (lib/servidor/mesmaOrigem.ts, CSRF); limite de tentativas de código por instância (lib/servidor/limiteTentativas.ts); `voltar` passa por destinoSeguro. Páginas da conta são noindex.
- Meu Radar: um radar por conta (radares), busca pelo perfil com no máximo 12 termos relacionados no total; contagens por radar_contagens; grátis vê os 5 primeiros (no servidor) e abrir o radar não gasta busca.
- Textos do PNCP só passam pela limpeza de lib/texto.ts (sem IA); siglas novas entram na lista SIGLAS. Título do edital = assunto() (sem a abertura burocrática).
- Página inicial em três colunas a partir de lg (1024 px). Abaixo: uma página só que rola, com o mapa em cima (58svh) e a lista embaixo; barra fixa embaixo (Mapa · Lista · Alertas · Planos, components/BarraCelular.tsx, `--altura-barra`; a rolagem só acende o item, nunca escreve o endereço); busca compacta com "Filtros (n)" e folha de filtros (rascunho; "Ver N editais" por /api/contagem, que não conta). Tocar no card abre o edital. Escolher um município leva o mapa até ele (com raio, enquadra o círculo; sem filtro, volta ao Brasil): decisão em `focoDoMapa` (lib/geo.ts). `ALTURA_GAVETA_RECOLHIDA` (0) continua exportada para o Mapa.
- Limite do grátis: 3 buscas e 3 editais diferentes por dia (Brasília) por navegador (`em_visitante`, garantido pelo proxy.ts); Basic 15/15, Pro uso justo 300/300 (`LIMITES_PLANO`); o dono sem limite e sem faixa. Faixa do plano grátis abaixo do cabeçalho em todas as páginas (components/FaixaPlano.tsx, bolinhas = restantes; amarela com 1, laranja com 0). Busca = termo (sem acento/maiúsculas/espaços) + UF + município + valor + modalidades + órgão + raio (prazo e página não contam; com raio a UF não entra; vazia não conta); chave = sha256 (lib/limites.ts, lib/servidor/uso.ts). Lista e mapa mandam os mesmos parâmetros (contam uma vez). Banco fora na contagem: libera.
- Sinal de limite: HTTP 402 `{ erro, codigo: 'limite_diario', limite }` em /api/busca, /api/mapa e /api/exportar (429 é só limite por hora). Essas rotas e /api/uso respondem `private, no-store` (sem cache no CDN). A página do edital conta no servidor (só depois de achar o edital) e, bloqueada, troca tudo abaixo do cabeçalho pelo cartão dos planos (seção nova entra dentro desse bloco). Links para /edital e para `/?q=` sempre com `prefetch={false}`; sem loading.tsx no edital nem Cache Components.
- Busca no endereço: a página inicial lê e escreve `/?q=&uf=&municipio=&valor=&modalidades=&orgao=&raio=&dias=7&tela=lista` (lib/urlBusca.ts) e guarda o estado ao sair (lib/cliente/volta.ts) para voltar do edital no mesmo lugar. Escrever o endereço só por `trocarEndereco` (lib/cliente/endereco.ts): `history.replaceState(null, …)` apaga o estado do Next e o Voltar deixa de funcionar.
- /planos: tabela Grátis · Basic R$ 49,90/mês ou R$ 499,00/ano · Pro R$ 89,90/mês ou R$ 899,00/ano (anual = 10 mensalidades; preços em centavos em lib/planos.ts; Pro sem nenhum teto; cartões abaixo de md; alternador Mensal | Anual), lista de espera (`lista_espera` com `periodo` mensal/anual desde a 0010, /api/lista-espera, 5 por hora por IP) e evento `quer_recurso` plano_basic/plano_pro. Com o pagamento ligado, "Assinar" vai a /api/checkout e dali à Cakto (a lista de espera só aparece com o pagamento desligado).
- Pagamento (spec docs/superpowers/specs/2026-10-18-pagamento-cakto-design.md revisão 2, plano docs/superpowers/plans/2026-10-18-pagamento-cakto.md, 0015): só Grátis e Pro (R$ 37,90/mês ou R$ 349,90/ano; Basic fora de linha, `'basic'` só como valor antigo). Checkout próprio em /assinar (sem login antes): nome, e-mail, celular, CPF/CNPJ; Pix Automático (QR desenhado no navegador, espera por /api/checkout/estado) ou cartão (SDK `https://cakto-sdk.pages.dev/cakto-sdk.min.js` com o `client_id`: createToken → authenticate3DS com endereço → antifraude; número e CVV nunca vão ao servidor). POST /api/assinar cria a cobrança (`/public_api/payments/`, X-Idempotency-Key; o `metadata` público só aceita utm_*/sck, então o código do checkout vai em `metadata.sck` e volta no webhook em `data.sck`). Interruptor = `configPagamento()` (CAKTO_WEBHOOK_SECRET, CAKTO_CLIENT_ID, CAKTO_CLIENT_SECRET, CAKTO_OFERTA_PRO_MENSAL/ANUAL). Webhook /api/cakto (HMAC, idempotente) cria/estende/cancela/estorna `assinaturas` (mensal 31 dias, anual 366, +3) e liga o navegador do checkout. Pro de quem está na página: `planoAtual(ctx)` (lib/servidor/plano.ts) = dono, assinatura do navegador ou assinatura válida pelo e-mail da conta logada; /obrigado leva a /entrar?email=…&voltar=/radar/comecar. Cadeados (só com o pagamento ligado): grátis sem link oficial, 3 parecidos, sem raio/órgão/exportação (402 `recurso_pro`). Ofertas Pro irpv92e/iuy9gzb (Basic t8o4sst/m2nvms3 desativadas); webhook 75009; `npx tsx scripts/cakto.ts listar|pedidos|preco-oferta|desativar-produto|sondar-pagamento`. Resumo semanal do Pro: sessão da Fase 4.
- Medição (entrega 3): Google Ads conta 988-698-8976 (`GOOGLE_ADS_CUSTOMER_ID` no .env; skill google-ads, `conversions` lista os rótulos), tag AW-18520543547 em components/TagGoogle.tsx com Consent Mode v2 (tudo negado até o "Aceitar" do aviso de cookies, escolha em localStorage `em_cookies`). Conversões (lib/medicao.ts, `medir` em lib/cliente/medir.ts, `<Medir>` em componentes de servidor): assinou (principal, /obrigado, valor + transaction_id + e-mail para conversões otimizadas), checkout, limite e buscou (secundárias, uma vez por dia).
- Entrada pelo CNPJ: /cnpj (página de destino, indexável) e link abaixo da busca da página inicial. GET /api/cnpj/{cnpj} (BrasilAPI com User-Agent próprio, cache de 30 dias, 20/h por IP, nada gravado além do evento) → empresa e assuntos pelo CNAE (lib/cnpj.ts: mapa de prefixos de CNAE para os 14 assuntos; os da atividade principal vêm marcados, os das secundárias desmarcados) → link `/?q=termos&uf=` (conta como busca).
- Dono confiável: `em_interno=1` (/sobre?interno=1) só tira as visitas das métricas; com o pagamento ligado não libera nada. Sem limites e com o Pro só o cookie `em_dono` (HMAC de 'dono' com `INTERNO_SEGREDO`), gravado abrindo /sobre#dono=<INTERNO_SEGREDO> (depois do #, fora dos logs). Ao trocar de domínio ou de navegador, remarcar e fazer uma busca (os cookies são por domínio).
- GitHub Actions em repositório privado: 2.000 min/mês; 8 rodadas/dia precisam ficar em média abaixo de ~8 min (≤ 66 min/dia).

## Comandos
- npm test / npm run typecheck
- npm run worker:seed: municípios
- npm run worker:backfill -- --dias 30 --ufs BR --proposta [--proposta-ate aaaa-mm-dd]
- npm run worker:sync: sincronização incremental (UFS=BR para o país inteiro)
- UFS=BR npm run worker:conferir -- --amostra 20 [--ufs-abertas SP,BA,AM] [--proposta-ate aaaa-mm-dd] [--idempotencia]
- npm run worker:reler-itens: regrava palavras e resumo dos itens das compras abertas (depois de mudar a regra do resumo)
- npm run db:aplicar -- supabase/migrations/NNNN_nome.sql: aplica uma migração (uma transação)
- npm run db:medir [-- --vacuum]: tamanho do banco e das tabelas
- npm run dev / npm run build: site
- npm run gerar:estados: contorno das UFs do mapa (public/geo/estados.json)
- npm run capturas -- <url> [slug1 slug2 …]: capturas de tela (precisa do Edge invisível na porta 9333)
